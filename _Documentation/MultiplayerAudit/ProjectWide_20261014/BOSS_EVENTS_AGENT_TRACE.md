## Health, unload and lifecycle

Native World spawn callback excerpt confirms EntityLoadedDelegates executes before AddEntityToMap/Entities.Add/OnAddedToWorld. WorldHooks installs only on authoritative world, detaches prior hooks and clears pending state on replacement. Loaded tracked entity marks NeedsHealthRestore and enqueues generation token; ProcessPending budgets16 per update, retries absent entity8 times with exponential world-time delay and leaves restore flag if probe expires. Old generation tokens are discarded. Unload captures live health and retains tracked state only for Unloaded reason; other removal clears tracked membership or completes killed boss. Pending queue can retain stale tokens after cancellation until drained; no indefinite gameplay reservation is attached to them.

Health snapshots store absolute HP/max plus fraction. Restore keeps absolute if same max, fraction otherwise, clamps and preserves min1 for positive fraction. Continuous loaded entities refresh snapshots; reconstructed/missing-role-buff entities restore before normal capture. Initial full fill only for new spawn after expanded max becomes visible. If role maximum was already expanded when first spawn snapshot was captured, NeedsInitialHealthFill remains true until a later expansion; no automatic current full-heal claim is made, but the flag is not cleared in that case. Legacy +30000 self-health action is blocked for tracked targets by a precise MinEventActionModifyStats.execute prefix. Guard is runtime/server-registry scoped and does not use buff-name guesswork. DEBUG broad stat/entity hooks only observe/log, bounded verbose windows; no health mutation originates in them.

Lifecycle pumps1s server-side: prunes actually dead loaded supports/regulars, maintains surviving targets, retries RewardPending and manages reward lifetime. Null entity with persisted boss-role record means unloaded and is retained; boss missing without record has300-world-tick grace then Failed. Actual dead boss completes immediately through native EntityKilled or observation. Native EntityAlive.OnEntityDeath5439–5480 invokes EntityKilled before dropItemOnDeath on nonremote entity, confirming support custom-bag publication can suppress native drop afterwards. Boss defeat removes boss role before reward; completed encounter still maintains surviving supports/regulars. Archive eligibility requires terminal state, no reward, empty support/regular lists and no tracked state; archive bounded4096. Failed events return before pruning/maintenance, so surviving members of a failed encounter can prevent archive indefinitely; no whole-world cleanup policy is implemented here.

## Rewards, native access and packets

TryIssue server-gated, requires progression/not-issued, finds floor/air site within5m of last boss position then creates native stationary loot entity. It sets spawnById=progression.OwnerEntityId, name, allowShare=false, OverrideLootList=airDrop and OverrideName=sc_General before native spawn. It then commits event reward entity ID/issued/placed/expiry(world+72000)/Completed; notification occurs before MarkDirty. Failures before create leave RewardPending for retry. Support SpawnSupportBag returns true only after native spawn+scale+sound; failures try removing the bag and allow native loot fallback. This is exception compensation, not a durable exactly-once crash protocol.

## Concrete findings

**BOSS-A — reward entity owner restriction is lost on native disk reload (high authority relevance).** New entity reward creation3630+ sets transient spawnById once. Native ECD fields default spawnById=-1; both read and write serialize spawnBy fields only when stream mode!=0. Fully read StreamModeRead/Write show Persistency=0. Native Chunk write/read excerpts choose Persistency for disk. ApplyToEntity always assigns the omitted/default spawnById to entity. Native Entity/EntityItem/EntityContainerAbs/EntityLootContainer persistence has no alternative spawnBy serialization. Boss WorldHooks.OnEntityLoaded only accepts tracked combat entities from Registry.Entities; reward entity IDs are absent there. RewardService.Update only updates location/expiry; does not rebind owner from stable event owner. Legacy RewardAccess registry deliberately excludes RewardEntityId>=0. Therefore a saved/reloaded reward crate reaches native lock authorization with spawnById=-1 and accepts any actor, subject to ordinary native lock availability. Before disk reload, a reconnect with changed player entity ID can instead deny the rightful stable owner: OwnerNetwork updates event progression ID but not crate.spawnById. Actual entity-ID reassignment incidence not run; disk omission is concrete source behavior. Restore native restriction from durable stable ownership on reward load/reconcile and verify server lock admission; do not replace native inventory transfer.

**BOSS-B — unloaded reward expiry/cancel forgets removal obligation.** RewardService.Update null reward entity preserves record until expiry, then MarkRemoved clears reward ID/placed and later permits archive; no persistent tombstone/deferred removal is retained. WorldHooks ignores noncombat reward on future load. Native Chunk persists EntityLootContainer stubs and later spawns them; native age counter is runtime-only and resets on reconstruction. An unloaded saved reward can therefore return after custom expiry until native age/empty cleanup. Release cancel similarly TestTools.RemoveEntity erases role record then removes only currently loaded world entity, and CleanupEvent drops event record; it does not remove unloaded chunk stubs or queue exact-ID removal. Such survivors lose event reconciliation/cleanup (combat entity immortality after reload depends native saved buff/lifetime state; not asserted). Preserve exact entity identity removal obligation until native absence is witnessed across load/save.

**BOSS-C — corrupt/unsupported load has no mutation quarantine.** Load3195 resets registries, catches primary/backup failures, resets and returns; no loaded-failed state gates Director, TryStart or Save. LoadFile stages schedules but imports events/entities directly into registry while parsing; catch reset removes partial imports. Missing-primary backup recovery is supported and publication helper uses File.Replace+backup, so do NOT repeat old delete-before-move allegation. However failed recovery followed by natural queue creation or unconditional WorldShuttingDown Save can overwrite unreadable state, replacing backup on later publication. Release diagnostic Write is conditional DEBUG and calls are omitted: load failure itself is silent in Release. Existing MP-021/other failed-load-quarantine family overlaps; this is distinct boss-store impact on encounters/rewards, not a claim about current save corruption.

**BOSS-D — v105 supply-crate migration destroys source before replacement.** Update3520+ removes loaded old EntitySupplyCrate before TrySpawnEventRewardCrate. If replacement fails, it records failure but leaves RewardEntityId pointing to removed old entity, RewardIssued/Placed true and Completed. Next Update sees null until expiry, then removes record; no replacement retry or source contents custody remains. Old loot contents are not migrated on success either; new crate regenerates airDrop on first native opening. Legacy block migration is stronger: replacement first, exact block revalidation, removal postimage and compensation. This finding is v105 compatibility only, not normal new reward path.

**BOSS-E — native world and sidecar publication are not one recoverable reward transaction.** Reward issuance/death/loaded entity state is changed in memory; sidecar saves on60s dirty cadence and native chunks save separately. WorldShutdown saves boss sidecar before native SaveWorld (native GameManager.SaveAndCleanupWorld verified). A crash between saved sidecar and native entity publication can retain RewardIssued with missing crate, or native reward persisted before sidecar can leave a retryable reward event without its receipt. Current code waits missing reward until expiry rather than proving/reconciling delivery. This is a source-visible interruption window, not an executed dupe/loss. Bound correction to event reward/native entity receipt and save witness; no generic server-inventory rewrite.

**BOSS-F — shutdown save is not authority/saving-mode gated.** OnStart loads only AsServer; periodic SaveIfDue rejects remote world, but registered OnWorldShutdown always calls Persistence.Save after server-gated CaptureAllLoaded. Native GameManager.SaveAndCleanupWorld invokes WorldShuttingDown before its IsServer && bSavingActive && !IsEditMode save gate. Consequently client or saving-disabled shutdown can publish its empty/new boss registry to dynamic GameIO save path; exact remote client's directory/path collision was not inspected and no server-file overwrite is claimed. Separately, authoritative failed shutdown Save is caught then GameShutdown clears registries; retry state is lost. Align shutdown ownership/path with the same authoritative world that loaded the store and retain failed-save state, respecting intended native no-save mode.

Installer early flag issue is existing MP-013. No packet spoof bypass is claimed; no global-authority redesign recommended. No test-suite PASS text in this source was treated as executed validation.
