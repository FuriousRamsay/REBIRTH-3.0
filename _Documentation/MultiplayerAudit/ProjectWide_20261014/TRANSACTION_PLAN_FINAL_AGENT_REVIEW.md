# Transaction plan final independent review

2026-10-15. Review-only; no implementation/build/game/tests. Scope MP007–010,018,024,031,048,054–056,066,068,072,073 against current report, execution draft and completed source/native evidence. This document resolves choices supported by accepted architecture, lists facts still required, and proposes one coherent vocabulary without mandating a new global transaction service. No fresh full-source credit and no runtime PASS.

## Architecture decisions already supported

1. Native owner inventory remains owner-authoritative. Server remote live bag is a join-time replica; authenticated latestPlayerData blobs and operation-correlated native owner applications are evidence, not permission to overwrite all owner slots. Existing offline/listen native actions remain first-class, not an entirely different conservation contract.
2. Every introduced cross-custody action needs one original identity and a retained terminal outcome. Existing compatible receipt/journal machinery is preferable to competing refund systems, but domain records need not be forced into one schema. Owner transfers, logical NPC revisions, station queue state and world crop state have distinct native publication boundaries.
3. Correlate by world/save+stable owner+creation+original operation+source incarnation/item. Native entity ID, UI session and connection token are live admission bindings. They must not become the sole durable owner identity. Reconnect reauthentication may rebind the live entity/session only after proving the retained original and current owner; it cannot blindly rewrite actor IDs in old immutable receipts.
4. Relevant exact slot deltas/item images are application authority. A full owner snapshot may be read for validation/planning under a hold; it is not an unsolicited resynchronization payload. Denial never carries a stale bag replacement. Lock the smallest demonstrably sufficient mutation scope supported by current guards; do not shrink whole-owner holds without proving all intersecting native actions are covered.
5. Missing ACK, timeout, failed setter or missing receipt is UNKNOWN, not refusal. Refusal is established before effects or by authoritative evidence that none occurred. Compensation reverses only a known committed leg into a compatible still-owned destination; no whole-plan blind refund.
6. Once physical output/ingestion/credit or another irreversible effect occurs, recovery settles that original effect and remaining legs. It must not restart the entire user action or rely on native recipe refunds as proof of original payment.
7. Bounded caches may evict terminal presentation after durable outcome retention; unresolved originals/remainders cannot age out. Busy/session flags are transport state and may be reset with correlation; custody evidence survives UI close, disconnect, unload and process restart.

These are choices resolved from accepted native-owner architecture. They do not require another user permission round. They also do not authorize native save/disk-confirmation redesign, server inventory replacement or broad disabling of existing actions.

## Protocol compatibility and migration

New schema fields must version existing records and read older records without manufacturing settled proof. Preserve exact original raw bytes for unsupported/ambiguous legacy records and expose retained/repair-required state; do not initialize empty replacement. New request APIs negotiate or refuse unsupported peer capability before any debit. Do not accept user/client-supplied terminal state as authority. Transport retries are bounded and query original; durable pending records are not dropped when retry budget ends. Save/world change keeps old unresolved operation under its original scope and prevents publication into a new save.

Reusable primitives should be limited: stable authenticated scope, complete native item codec, exact before/after/delta matcher, original receipt query, truthful publication outcome and hold ownership. Keep source-specific revision/reservation/ACL and effect witnesses in domain adapters. A global catch-all compensator cannot infer NPC logical quantities, crop incarnation, currency effect, native queue completion or overflow ownership.

## Recovery classifications to encode before implementation

- BEFORE proven and no attempt: authenticated cancel or apply existing original, according to recorded user intent; no newly invented action.
- AFTER plus original receipt: acknowledge/reconcile counterpart; never reapply owner mutation or side effects.
- Mixed known committed legs: finish/compensate only those proven legs with exact current compatibility and retained remainder.
- Unknown physical effect: retain custody and surface pending reconciliation; automatic retry waits for an actual native witness.
- Stale live session with durable original: retire transient transport, retain original and require fresh authenticated resume binding. Replacing entity ID alone is insufficient authorization.
- Invalid/unsupported record or failed store load: preserve evidence, block destructive publication and new conflicting operation; do not claim canceled or empty.
- Terminal A delivered while B current: answer A without occupying B or resetting B. Terminal archival is original-ID scoped.
