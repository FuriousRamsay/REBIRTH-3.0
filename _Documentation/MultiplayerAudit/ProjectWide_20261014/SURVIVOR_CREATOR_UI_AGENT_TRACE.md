## Creator session, model and persistence

Authorized opens configure a model and arm a static serial; OnOpen consumes it, rejects unarmed opens by close-only on next Update, and creates a model if needed. Fresh authorized opens capture original global native appearance, refresh definitions/store, reset selection/scroll/editor state, and restore input. OnClose preserves the draft only for suspended native picker/child editor/progression explorer, clears render bindings, removes editor handlers, unregisters custom scroll authorities, and otherwise restores original native appearance and nulls model/callbacks. The original native selection restore explicitly ProfileSDF.Save()s in Creator; Manager restores its original selection via preview bridge on close. No world character is edited by these projection helpers.

ViewModel owns selected background/diet/traits and bounded native appearance association. It revalidates step navigation, prunes incompatible traits when background changes, rejects conflicts, permits removal of previously selected traits, and requires exact zero point balance for local persistence/first-world confirmation. Restricted traits need matching background permission on both sides. Review purpose is read-only. Profile name rules max48/no CR LF TAB differ deliberately from native appearance's max30. Native profile name presence alone is not an existence proof; UI current native list/selection supplies appearance admission. CreationChoices are bounded separately from server progression selection.

SaveLocalProfile creates through ProfileStore or reloads the current record by editing ID, applies current draft selections, and calls TrySaveEdited. It is reusable local profile persistence, not authority to alter an existing saved world character. It has no captured modified-time compare in the creator. Manager delete does capture target ID+ModifiedAtUtc and rechecks both before deleting; duplicate names inspect allProfiles instead of filtered rows. Store atomicity/compatibility rules remain prior creation/repository evidence, not reread here.

Creator Save captures callback/model before CloseAndReset, so synchronous OnClose nulling fields does not lose the normal callback. Local cancel similarly captures callback; CloseAndReset sends saved(null) once for cancellation. FirstWorld confirmation checks runtime installed, name if reusable requested, valid exact-point selection, then calls captured external callback. FirstEntry StageSelection:713–804 reread validates current mode and ValidateForCommit, clones selection/choices, stages without server mutation, and defers RequestCommit until local player exists. Network RequestCommit copies bounded source-profile CreationChoices; authoritative identity/commit/receipt/persistence remains the network/creation traces. A selected local profile cannot select a remote repository identity.

The creator's first-world-only legacy profile rows and external entry APIs remain distinct from active ProfileManager create-local flow. Active manager create closes manager, creates reusable profile, then reopens fresh manager and refreshes selected ID. In spawn mode the native underlay remains preserved. Review/background skill/knowledge links are CreatorPreview requests with registered return tokens and suspended draft; OnClose unregisters tokens on real exit. No progression award occurs from those buttons. Paging/food presentation is local and honors existing disabled Release paging policy; geometry, conflict summaries, item icons and projected starter-package lists do not move inventory.

## CREATOR-UI-A: native Apply hotkey bypasses REBIRTH-owned editor completion

Concrete reachable source issue, conditional on native HotkeysAllowedFor admitting the editor's normal Apply key release; no runtime reproduction performed. Existing-profile and temporary editor paths both hide stock btnApply/btnBack and show owned overlay buttons at Creator:3505–3551. Native custom editor Update independently checks GUIActions.Apply.WasReleased and schedules BtnApply_OnPress with RunTaskAfterFrames; it does not press the hidden UI control or consult its visibility. Native GUI Cancel similarly schedules stock Back. REBIRTH native guard:8–14 only observes PermanentActions.Cancel and calls owned Back. No CustomCharacterWindowGroup Update/Apply patch was found by actual source caller search.

Temporary creation sets suspendedForNativeChildEditor and EditingTemp before opening native editor (Creator:3327–3370), whose synchronous close preserves model. Owned overlay Apply captures current appearance, performs OwnWrite temporary save, closes native editor, sets AwaitSaveName, and explicitly resumes Creator (3559–3636). Owned Back explicitly cleans and resumes (3638 onward). Native stock Apply instead saves current ProfileSDF profile when hasChanges and closes native group. It does not call either owned callback, does not set AwaitSaveName, and does not ResumeCreatorAfterNativeChildEditor. Native CustomCharacterWindowGroup.onClosed is only assigned by its static Open API; this creator opens the group directly via windowManager, not that API. The closed creator's Update cannot be the normal recovery driver, as its own source comment already recognizes when wiring callbacks synchronously. Even if an exceptional update ran, Tick EditingTemp sees nativeEditorDecision0 and cancels rather than honoring Apply/name-save.

When hasChanges causes stock SaveProfile on an existing RBTemp profile, full WriteGuard:33–44 explicitly revokes temporary ownership before allowing the native save: outside OwnWrite is treated as public adoption. Subsequent silent cleanup requires positive ownership (Bridge:2285 onward) and preserves the profile after revocation. Thus this input path can both bypass the creator's naming/resume workflow and convert an internal temporary appearance into a preserved local profile. This is local UI/profile lifecycle, not a remote creation duplication or unauthorized other-player mutation. With no hasChanges the adoption part does not occur, but stock close still bypasses owned completion. Native hasChanges is set by native preview update; actual hotkey mapping/order and observed blank-screen duration need a later authorized game test. InGame also lacks the Menu guard rect, so do not claim its Escape path is equivalent without independent native action routing proof.

For existing custom-profile edits the same stock hotkey can save directly and close without owned FinishExistingPlayerProfileEdit/resume. Appearance changes are already explicitly authorized by choosing edit; the defect is completion/navigation ownership, not a write-authority violation. Keep the former positive-ownership receipt/guard design intact; any future correction should bind native keyboard/controller completion to this creator session rather than weakening cleanup ownership.
