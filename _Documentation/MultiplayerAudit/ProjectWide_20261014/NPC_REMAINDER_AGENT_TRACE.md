## Authority, persistence and old appearance paths

Foundation humanoid Init1152 onward calls base.Init first, loads saved aggregate HumanAppearance only with matching profile on authority, otherwise makes a concrete descriptor from pipeline resolver and stable seed. If a matching aggregate record exists and descriptor SDCS unresolved, AuthorityResolver selects current native text choices, TryCommitResolvedAppearance durably commits them before model adapter initialization and runtime publication. Existing saved resolved descriptor wins; SetHumanAppearance refuses reroll. This active per-entity Init is independent of missing population dispatcher, so manually/native-spawned authored classes still consume this path.

AuthorityResolver qualifies native text catalogue <=4MiB, seeds System.Random from descriptor, selects required race/variant/eye and optional hair/facial pieces in legacy order, and returns strict composed fields. SdcsCatalog hashes the text asset, calls native SetupData when hash/definitions change and refuses absent/incomplete definitions, including dedicated servers. It does not load visual meshes or accept client choices. Existing fingerprint cache is process-global but refreshed against resource content/definition presence; no stale cross-save appearance mutation identified here.

On clients a visual is also initialized before its authority descriptor packet arrives. Thus do not claim all visuals always use persisted resolved choices or all fresh ordinary NPCs are atomically authored by authority. Legacy same-seed generation assumes same catalogue ordering; differing assets can diverge. No actual mismatched installed-client catalogue or visual divergence demonstrated. Later aggregate capture stores descriptor; no automatic second pass resolves it in these files alone until initialization path runs again.

## Materialization, dedicated, fallback and retries

EModel.Init deliberately bypasses player-specific SDCS.Init and records native entity/class/model parent without generating a model. SetSkinTexture no-ops; SwitchModelAndView invokes EModelBase via explicit nonvirtual method delegate only after rig/modelName exist, avoiding native playerEntity assumptions. Actual installed EModelBase/SDCS contracts were not independently decompiled in this tranche; comments mentioning3.2 do not override operating target3.0b259.

ApplyAppearance validates SDCS then resolves either saved exact choices or legacy seeded choices, destroys prior generated model, generates and records applied flag. Saved resolved materialization checks sex/model/generator, current catalogue hash, archetype, race/variant/eye/hair names and refuses unavailable choices; it never rerolls missing saved parts. On dedicated, generated visual is skipped and applied=true, invisible. This is visual success only, not proof physical head/rig/collider/native reconstruction is qualified (prior native helper requires exact geometry separately).

Client mesh failure returns false; RefreshAppearanceMeshes retries generation up to three counted attempts, then no-op. Refresh is reached from model equipment refresh, native equipment bridge, appearance package and prepared restoration path; no autonomous retry timer found. ApplyAppearance while !applied can restart attempt count for a new initialization, so the three limit is not a global lifetime/network retry cap. Source proves retry triggers, not eventual recovery. A successful refresh regenerates meshes and reassigns equipment transforms. Old model is destroyed before replacement generation, so a local materialization failure can leave invisible/partial visual; runtime state publication is deferred by ApplyReplicatedHumanAppearance, but previous meshes are not restored. No real unavailable mesh fixture reproduced.

Foundation fallback to Custom only applies unresolved SDCS and configured non-Fail; resolved appearance forbids fallback. Custom adapter rejects EModelRebirthSdcsNpc itself, so authoring SDCS ModelType cannot become a Custom CLR model at runtime. Current included XML explicitly Fail, making this refusal deliberate; do not propose enabling fallback as audit repair.

Its IsAnimationWithMotionRunning returns true whenever animator is enabled (OR movement flag); exact native consumers beyond AvatarController declaration were not present in extracts searched, so no pathing/damage behavior is inferred. Native rig/animation tests remain needed; source model success is not animation/gameplay PASS.
