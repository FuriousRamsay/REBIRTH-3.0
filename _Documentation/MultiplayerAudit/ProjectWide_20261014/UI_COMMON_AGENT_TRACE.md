## Input style subscriptions versus native lifecycle

InputStyleSubscriptions replaces per-widget multicast entries with one Hub per PlayerInputManager. Each hub stores weak listener references, prunes dead nodes on change, and forwards the exact native controller/label OnLastInputStyleChanged callbacks. Per-object ConditionalWeakTable subscription prevents duplicate registration. Event accessor interception is limited to XUiController/XUiV_Label targets with exact callback method name; other listeners retain native add/remove semantics. Controller Cleanup prefix removes the record and resets registeredForInputStyleChanges. Native label Cleanup removes the intercepted event through the event accessor patch.

Direct native reads confirm XUiController.registerForInputStyleChanges normally sets registered flag and subscribes callback; native callback only updates curInputStyle/forceInputStyleChange. Native XUiV_Label.Init subscribes directly, Cleanup unsubscribes and its callback requests text reformat when action markup is present. Both routes are covered. Cleanup now removes the subscription before native Cleanup; resetting the flag makes native conditional unsubscribe unnecessary. Weak listener design does not pin old controller trees through the input manager. Hub event is not detached while manager lives, but its controller records are weak and empty hub is bounded to that manager. Replacing the input manager while retaining a subscribed controller does not migrate subscription automatically; ordinary UI Cleanup/recreation is the observed design, no reachable replacement-without-cleanup proven. No network/persistence mutation in this subsystem.

Install patches four classes through PatchClassOnce. It has no local installed boolean; core bootstrap named-step controls repeated calls and per-class once handles successful retry. Failure midway can leave a subset attached; this is the existing MP013 family, not separately numbered here. No automatic rollback in this file. Native callbacks are local UI state, not character authority.

## HUD slot guard and shared window visibility ownership

HUDStatBarSlotGuard validates native currentSlotIndex against actual inventory.Length. If invalid, it uses valid inventory.SelectedSlot; if neither valid it clears itemClass/attackAction/ammo fields and skips native setup. Native setupActiveItemEntry directly indexes inventory.GetItem(currentSlotIndex), so guard covers real out-of-range seam. It preserves valid indices and actual native Hand transient model. RebirthWindowHudScope full source: per-XUi dictionary holds one snapshot of visible/enabled state and transform scales, reference-counted across overlapping owners. Discovery is global Resources managers, intentionally presentation-only; modal visibility follows primary player. Split-screen/multiple local UI behavior is not established. ## Loose-stone return routing closure

Full25-line routing patch restricts change to current Rebirth world, exact resourceRockSmall, actual EntityPlayerLocal inventory owner and exact same xui.PlayerInventory.Toolbelt instance. It declines native ReturnItem only when real Backpack.CanTakeItem succeeds. It inserts/debits nothing and does not change supplied count; returning false selects the native caller's next branch. Native Inventory.ReturnItem itself only searches preferred slots and delegates AddItemAtSlot. Thus patch changes preference/order without replacing conservation/publication for successful owned local insertion. If backpack capacity changes/refuses between CanTakeItem and actual AddItem, native toolbelt fallback still runs. Other server-side inventories and remote entity replicas are excluded by EntityPlayerLocal check. This does not certify all third-party AddItem callers, rejected setter/hold semantics or startup recovery described in earlier trace.
