## Dispatch boundaries

ConnectionManager.Update iterates current Clients, skips a disconnected primary connection, and processes each client's channels with ToClient as the disallowed direction. The client processes only its connected server transports, disallowing ToServer. ProcessPackages rejects that direction and rejects packages not AllowedBeforeAuth while client loginDone is false. It supplies the current GameManager.World at dispatch, calls ShouldProcess, invokes ProcessPackage and frees the pooled object. The alternate HandleSkipped path owns its cleanup.

Consequently, a ToClient declaration is actually enforced by this native dispatch path. Missing an extra IsRemote check inside a ToClient handler does not alone establish a server-write exploit. Direct calls, Harmony interception, deserialization before dispatch, deferred work and world/session changes still require independent tracing. Sender assignment occurs below the reviewed layer and remains pending. The native base defaults ReliableDelivery=true and Channel=0, but protocol-specific ordering, framing and maximum sizes have not yet been proved.

ValidEntityIdForSender compares Sender.entityId on the server and accepts on clients; ValidUserIdForSender accepts either the sender's platform or crossplatform ID. Neither helper independently establishes liveness or a retained callback's current-session membership. Native Update's iteration provides a current connection context for immediate dispatch, whereas deferred handlers need their own lifetime treatment.
