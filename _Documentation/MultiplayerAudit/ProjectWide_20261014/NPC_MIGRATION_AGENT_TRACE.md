## Separate progression XML import

AdministrationSupport480–485 confines progressionimport filename to Path.GetFileName under current save, requires Repair through the same policy, defaults to merge, and invokes ProgressionPersistence.ImportFrom. ImportFrom requires server, parses all data then ImportRecords and marks dirty, but does not save or publish/bump replication. ImportRecords73 replaces each matching NPC record wholesale even in merge mode (merge is NPC-row union, not entry union); replace additionally clears all records and replay GUIDs first. Global replay queue retains at most8192. Schema1 has no persisted global replay section; schema2 has it. These semantics need explicit administration acceptance before assuming merge preserves existing per-track entries. They are not a network replay exploit by themselves.

Confirmed source limitation adjacent to the already recorded reset replication issue: progressionimport does not bump ProjectionRevisionService or PublishDelta/PublishBaseline, so already connected client projections are not immediately refreshed by this command. Future ordinary delta/baseline events determine visibility. This trace does not claim the imported XML ComponentRevision is the projection revision; those are separate services, as prior network trace established. Ordinary award path explicitly bumps and publishes; import does not. No runtime client observation was performed.

Progression XML weak semantics (bad IDs skipped, integer defaults, later duplicate entries/rows, unknown-track preservation) and missing-file unexpected-boundary service retention are already in NPC_PROFESSION_AGENT_TRACE. Do not duplicate them as newly discovered defects. ImportRecords clamps/recomputes known tracks when definitions exist; it does not translate legacy professionXp strings automatically. ## Remaining identity serialization helpers

WorldIdentityLoad validates bounded canonical stable IDs, unique ambient IDs, profile/name text, valid ticks and exact root/version/attribute counts. It parses pending, replay and completion sections before publishing; rejects pending+replay collision and completion lacking replay/matching identity/profile. SpawnReplayCodec caps65536, requires bounded nonblank spawn:/promote: keys, rejects duplicates and emits sorted canonical keys. SpawnIdentity binds only actual Register return with current canonical runtime/native ID/profile, refusing unrelated or stale registration results. These helpers grant no owner permissions and do not themselves instantiate or publish a native actor.

Selective WorldIntegration595 onward uses WorldIdentityLoad then atomically replaces all identity/pending/replay/completion maps. Its shared PersistenceFile selector validates only root/version before this semantic parse; semantic failure blocks writing and throws, and does not revisit a semantically valid backup once a root-valid primary was chosen. This is a fail-closed availability/recovery limitation, not partial cache publication. Parent owns complete spawn/native release chain and prior coverage. Readiness of all pending/completion/native contracts must not be inferred solely from these four helpers.
