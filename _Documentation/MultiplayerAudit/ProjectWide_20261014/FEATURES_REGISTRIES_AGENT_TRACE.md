# Features reporting registries semantic audit — 2026-10-15

Scope:18 remaining Features planning/evidence/report registries. Audit only; no production/build/tests/game/Git/main report or coverage-ledger edits. Prior FEATURES_AGENT_TRACE and NATIVE_TRANSPORT reporting-state evidence consulted. These declarations do not implement the production feature families they name.

## Coverage method (not hash-as-audit)

Every executable method/property body was read from actual source, including report assembly, count predicates, filter predicates, Row constructors and fixed status accessors. Large repeated initializer tables were reviewed in grouped passes: record IDs, enum/bool/numeric assignments and schemas, then every declaration string field/Row argument. Blank lines/braces/comments and repeated prefixes were elided in those views. All initializer expressions were additionally inspected in a string-stripped structural pass; only static record construction/literal values and pure Row calls were present. Truncated output was followed by narrower rereads for table records and the DomainReport boundary. This is **full semantic source review with grouped declarative tables**, not a claim that all physical comment/brace lines were literally displayed or that running a traversal/hash certified gameplay. Hashes below identify reviewed snapshots; no listed test or command was run.

## Actual execution boundary

All18 registries allocate private static record arrays and return formatted strings. GetSummary methods count declarations by enum/flag; Get*Report iterates fixed arrays and filters with case-insensitive ordinal substring checks. Null/empty filter lists all. Matches null-record checks are present; arrays privately constructed with nonnull records. Most record DTOs have mutable public fields, but these registries expose no public record-array snapshot/setter, so ordinary callers only receive immutable strings. None performs XML/config/source-file discovery, network dispatch, native lock/state mutation, Harmony registration, save/load or build/test execution. No authority role is needed for read-only report calls. No persistent state or entity lifecycle is owned by these files.

Actual command reachability: all18 registry symbols searched across **all Scripts including ignored Debug files**. External callers are ConsoleCmdRebirthSys, dedicated ConsoleCmdRebirthNetPersistFresh and17 dedicated Debug command wrappers. Registry-to-registry consumer is FirstSliceNoGoGate.CurrentDecision used by previously reviewed inert HarvestSalvage adapter and crop manual preview policy; it does not install/remove patches or independently guard actual Debug attack replacement. No production mutation/installer consumes these registry policies as a mandatory runtime contract. No IModApi or HarmonyPatch attribute exists in the reviewed registries.

SDK production files remain compiled Release; dedicated command wrappers in Scripts/Debug are omitted by project Release rule and #if DEBUG. ConsoleCmdRebirthSys remains and exposes report subcommands; ConsoleCmdRebirthNetPersistFresh remains direct Release command with IsExecuteOnClient=true. Both direct BuildVerify wrapper and NetPersist wrapper read fully; other command references are partial caller inspection, not full-file credit. Source report methods being compiled in Release is harmless reporting availability, not release installation of their named future patches. Native console discovery/trust boundary is already separately traced; these routes only Log.Out returned text.

## Reporting findings / exact limitations

**REG-A — fixed planning statuses and stale smoke expectations are easily mistaken for current evidence.** SourceAuditWorkspace.CurrentStatus always MissingRequiredFiles; NoGo always NoGo; intake always pending. Smoke matrix expects all gameplay flags false/no consumers and all diagnostics false, whereas existing NATIVE_TRANSPORT full HotPathFeatureFlags evidence confirms MapMarkersReservationsEnabled=true with a real BossEvent marker consumer. Broad summary says gameplay remains disconnected although dedicated current modules are installed. These historical expectations are not runtime safety gates and do not prove current audit/build/test status. Treat as low-severity diagnostic integrity/documentation debt: label historical planning, distinguish declaration from execution/live check and preserve NotRun. Existing hot-flags stale-report observation overlaps, so do not create a duplicate multiplayer authority finding.

**REG-B — test/verification summary counts differ from broadened subviews.** FeatureTestMatrix summary stateful excludes DedicatedServer/PeerToPeer that GetStatefulReport includes. BuildVerify GetHotPathReport concatenates hot/object/reflection textual searches and may print duplicates. Counts/headings should name declared selection criteria rather than imply unique tested/verified feature coverage. No gameplay effect or inaccurate executed PASS is established: main BuildVerification/FeatureTest summaries explicitly say NotRun.

**REG-C — filtering is intentionally incomplete across displayed prose.** Matches generally checks IDs/enums and selected fields but omits Notes; e.g. PatchEvidence report displays Verification yet Matches does not search it; SourceWorkspace displays WhenRequired yet Matches omits it. Substring filters therefore are not complete searches of visible columns. Missing row message means no checked-field match, not proof no rule or source requirement exists. Diagnostic usability only.

No new server mutation/replay/persistence exploit identified in these read-only shells. No native/API/XML deep trace is needed to turn declaration-only text into a runtime path: there is none here. Production features named by tables require their own actual installer/caller/persistence audits, many already separately recorded. Individual constant-text phrasing is historical evidence only; current operating directives and human user requests take precedence.
