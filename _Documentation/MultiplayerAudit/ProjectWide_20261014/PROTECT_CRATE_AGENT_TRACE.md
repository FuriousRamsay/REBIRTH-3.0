## Findings / exact qualifications

**PC-A — disabling option leaves three live policies active.** HasDefenderMarker calls GetPersistedCrateEntityId without Enabled check. SetRevengeTarget prefix always nulls nonnull targets and SetInvestigatePosition prefix always returns false for marked entities, even disabled. OnPolicyChanged(false) deliberately preserves persistent identities while clearing transient targets, so these calls remain reachable after disabling. HealthStatPatch also does not check Enabled: any marked crate HealthMax CVar continues replacing BaseMax and skipping native Stat.Tick. Other targeting policies, defender Update and local target bar do honor option. Concrete partial-disable behavior; not a remote authority bypass. Restore only the intended native behavior on disable, preserving durable generated identity needed to avoid duplicate groups.

**PC-B — durable generated reservation has no resumable spawn phase.** Trigger durably marks SpawnsGenerated=true with zero defender IDs, then marks/refills native crate and loops SpawnEntityInWorld/RegisterDefender/EnsureTarget without catch/compensation. Exception or termination midway leaves a generated reservation and zero/partial defenders; subsequent Register restores Triggered and Update never invokes Trigger again. Even success followed by final sidecar save failure can persist native defenders without durable reverse IDs until next retry; CVar recovery helps if native entities persisted, but no explicit expected-count/per-slot completion exists. This is at-most-once admission with possible missing group, not a duplicate-spawn bug. Complete/record the original reserved group using bounded identities and native saved evidence; no global inventory changes.

**PC-C — sidecar records are never pruned on crate destruction and dead defenders.** RemoveCrate is declaration-only in all Scripts; OnEntityUnload only UnregisterCrate transient map. Crate dictionary Update removes dead/missing runtime entry, not durable record. RemoveDefender called only from ReleaseDefender when its loaded crate is dead; dying/unloading defender Unregister removes transient map and MaintainTrackedDefenders removes dead/null IDs from runtime list without ledger removal. Persisted missing crate leaves marked defenders idle and never reaches dead-loaded release. Therefore generated history accumulates toward4096 cap and stale defender IDs persist; at cap future generation is refused. No current cap exhaustion measured; entity-ID reuse corruption depends native allocator lifecycle and is not asserted. Preserve unloaded records but settle known permanent removal through exact incarnation/witness; do not blindly prune unloaded entities.

**PC-D — Stat.Tick replacement skips native health change bookkeeping.** Prefix sets protected BaseMax, clamps above-max value, then returns false for marked crate. Actual native Tick full method excerpt also folds regen, Gain/Loss passive, RegenerationAmountUI, SetChangedFlag and m_lastValue; all omitted. Therefore modified crate health avoids these updates on both peers. Whether damage packets independently publish health/target bar correctly requires full native damage/stat replication tracing and is NOT proved broken by this omission. Record as compatibility contract needing focused follow-up, not confirmed missing replication.

**PC-E — structural load validation accepts inconsistent indexes.** LoadFile overwrites duplicate crate IDs and reverse-defender IDs while loading without detecting cross-crate duplicates; duplicate crate records can leave orphan reverse mappings from overwritten older record. Negative/duplicate defender IDs inside one record are silently skipped; health/stage and trailing file bytes are not semantically validated. Normal writer builds consistent records and attach moves defenders, so this is malformed/corrupt-file handling, not evidence ordinary saves duplicate identities. Preserve failed-load quarantine while validating entire candidate before publication.

## Limits

No item conservation operation is implemented here: loot generation/opening/removal remain native. Complete native death/damage/stat publication, native AI path attack execution and spawn-composition selection are not certified by their hook names. Full source read does not imply runtime installation success. Persistent CVar IDs use floats; no practical allocator-range precision failure was demonstrated. Debug commands are local diagnostics (rescan rejects remote world); no DEBUG test or command was run. Tracer comment claiming always compiled is stale: actual #if DEBUG and Release facade are decisive.
