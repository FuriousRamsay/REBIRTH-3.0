## Bridge failures and trustworthy validation gate

MP014 request accounting alone is insufficient. Existing Bridge traces establish started UI/world/activation coroutines can continue after HTTP abandonment, global cursor/modifier writers overlap, normal-tail cleanup can leave drag/button holds, and /stop cancels movement/releases input without necessarily canceling an outer routine that starts another child. HTTP200/action-injected flags also do not establish required outcome. No runtime manifestation was exercised in this audit.

Small corrective package: propagate captured request/world/player/run generation and deadline through nested routines, use owned input scopes and finally cleanup at every held-input boundary, and define cancellation for the whole active operation. Preserve intentional hold=true API until explicit release. Serialize or reject overlapping exclusive cursor operations and attribute report/state to the original request. Validate timeout arithmetic before enqueue. Do not retry an uncertain mutation until original operation has terminal evidence. Existing owned /enterpoi is a reusable pattern, not proof all endpoints are owned.

Offline: abandon queued versus after start; throw after first yield; overlap old cleanup/new hold; world/player replacement; negative/overflow deadline; stop before child transition; duplicate completion; busy latch reset on exception. Assert single terminal response, balanced outstanding count, no future native input after cancellation, no successor input released by predecessor, no stuck modifier/counter. Do not fake native physics as offline proof.

Disposable host Bridge batch: real drag/click/activate/walk with short deadline, stop while nested approach waits, actual native inventory/UI postconditions and input release. Use cleararea+restore setup while guard stays ON. VehicleSequence currently requires guard OFF and therefore conflicts with AGENTS.md: do not run it as-is; change its admission/fixture to support guard-on or use existing native driver actions and observations. No instruction to disable guard is authorized by this draft.

Fixture Loadout can move inventory before invalid weapon/ammo refusal: validate all setup parameters and capacity first, retain/emit exact partial setup outcome if later native failure occurs, refresh native inventory in finally. Setup mutations must not be counted as behavior under test. Craft/cook agenda's any-positive-delta/any-COOKING predicates must be replaced with exact requested recipe, batch and total outcome observations for acceptance; zero new errors alone is insufficient. Loot busy/report/world lifetime defects belong to the same infrastructure ownership package before those endpoints supply acceptance evidence.
