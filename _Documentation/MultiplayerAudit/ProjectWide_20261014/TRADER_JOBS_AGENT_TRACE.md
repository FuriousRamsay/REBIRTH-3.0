## Confirmed findings

### TJ-A — Random refresh correlation is lost by the native quest-list wire format

JobListRefresh.PrepareJobsEntry remote branch: pending epoch/request, sends authenticated sideband intent then native NetPackageNPCQuestList.FetchList. Server prefix BeginServerGeneration consumes sideband; Generation:245 stamps each offered Quest.DataVariables with RebirthTraderListEpoch/RebirthTraderListRequest. ClientListArrived:502 requires TryReadOfferStamp matching original epoch/request before entering currentjobsN.

Fresh exact-installed-assembly NetPackageNPCQuestList type fully decompiled/read: QuestPacketEntry contains only QuestID, QuestLocation, QuestSize, TraderPos and POIName. read/write and SendQuestPacketsToPlayer never carry Quest.DataVariables. Fresh EntityTrader.SetActiveQuests method read fully: creates new Quest objects, assigns positions/giver/faction, adds only POIName. No REBIRTH extra serializer/transporter references for correlation keys exist outside this refresh/generation file pair. Therefore legitimate remote random list reply cannot contain required stamps; ClientListArrived ignores it and pending stays until next check/10second timeout. Host synchronous path does not use stamps and is unaffected. An empty list is also unstampable. This is deterministic source protocol mismatch, not runtime reproduction.

Correction after audit/checkpoint: carry exact request identity through a real response/correlated publication, retain native authoritative list and reject retired/reordered replies. Do not remove correlation checks to restore availability. Cases later: host, independent remote/dedicated, empty/generated list, delayed/obsolete/reordered reply, close/reopen/trader replacement, timeout/retry.

### TJ-B — Shared-member notifications authenticate the owner instead of the member

NotificationPolicy.cs installed RebirthSilentSharedQuestNetworkPatch obtains Sender.entityId then rejects RemoveQuest/AddSharedMember/RemoveSharedMember whenever sender != sharedBy. But installed SilentAcceptSharedQuestPatch sends Setup(questUniqueId,questCode,sharedByOwner,localAccepter,true) FROM the local accepter; SilentRemoveQuest and reconnect removal similarly send owner + self + false from member. Fresh native NetPackageSharedQuest.Setup overload inspected confirms bool=true maps AddSharedMember, false RemoveSharedMember. A legitimate remote member differs from sharedBy; server returns false before owner journal update/forwarding. Thus remote member acceptance/removal notifications fail; local receiver quest can still be accepted, so do not claim all quest acceptance fails. Local host membership path bypasses remote Sender condition; remote-to-host and remote-to-remote owner notification both affected. Native party member/reward behavior consequences beyond missing registration need grouped gameplay observations.

Correction: event-specific sender authentication (owner cancellation versus member acceptance/removal), current party/quest identity, preserve native membership and silent presentation. Do not permit arbitrary sender-owned sharedBy mutation. Later cases: host owner+remote member, remote owner+host member, two remote clients, member cancel/reconnect removal, owner cancel, wrong-party/wrong-code sender and duplicate notification.

### TJ-C — Remote authoritative POI completion history cannot resolve journal owner

PersistentHistory.GetStablePlayerId depends solely on journal.OwnerPlayer then persistent lookup by that entity ID. IngestJournalCompletions immediately returns when OwnerPlayer null/remote. Completion postfix only records when OwnerPlayer has nonremote world. Fresh exact-native PlayerDataFile.ToPlayer previously inspected in NPC_TRADE_AGENT_TRACE assigns questJournal.OwnerPlayer = _player as EntityPlayerLocal; native GameManager.RequestToSpawnPlayer creates server remote EntityPlayer and calls ToPlayer; SavePlayerData installs uploaded journal without assigning a local owner. Thus dedicated/listen server remote-player QuestJournal.OwnerPlayer is null in this native path. Server OnPlayerSpawned resolves player then invokes Ingest, which returns. Client completion postfix refuses remote world. No owner-ID argument exists in RecordCompleted, so remote personal completion does not populate server sidecar through these installed callbacks. Existing completed journal still supports local completion-count UI, which is a separate count path.

Listing server calls Build(journal) and AddRecentHistory using the same unresolvable owner identity, so server repeat-recency filtering for remote actor does not consume persisted remote history. Active quest identities still read journal. Concrete source gap, not proof of current user history loss. Local host/SP history works via EntityPlayerLocal. Native journal transfer may eventually carry completed entries but this service fails identity lookup; simply saving more frequently does not fix it.

Correction: pass authenticated runtime player/persistent identity from native completion/spawn caller with explicit journal binding, preserve native owner-local journal semantics and sidecar schema. Cases: remote finish and new board, reconnect/reload, host comparison, shared copies excluded, migrated old journal, loaded trader/chunk absence.

### TJ-D — POI history recovery remains writable and writer is copy-over-primary

PoiPersistence.EnsureLoaded stages/validates primary and backup, correctly tries backup for missing primary; both failure sets loaded=true without failed-load quarantine. Later RecordCompleted / spawn migration can save new/partial projection over both unresolved candidates. Save validates .tmp by reparsing (existing control), then copies primary to backup and tmp over primary, no shared flushed atomic publication. Reset(true) calls SaveLocked which catches failure, then clears Records/Watermarks/dirty; retry state lost. This is same persistence failure family as existing MP-012/MP-023 but distinct RebirthTraderPoiHistory.xml. No malformed user file or injected fault observed. Grace's delete-before-move + loaded-before-read remains existing MP-012, not renumbered.

Correction: preserve last usable candidates and dirty originals on failed recovery/publication, shared verified durable writer, observable save outcome before reset. Keep v1->v2 ordering migration/watermarks and 64-row policy. Cases later: corrupt/missing/unsupported primary/backup, interrupted copy, next retry, failed shutdown, grouped reload.

### TJ-E — Intended saved-journal completion fallback and revision hooks uninstalled

Three class declarations named above have no explicit PatchClassOnce references; actual installer includes OfflinePartyCompletion but omits saved-journal fallback and both cache revision hooks. In targeted mode they do nothing. Intended saved-journal postfix would scan newly installed journal after native30second upload, recovering party-complete notification arriving before server journal phase advances. Actual packet rejects when current server phase is stale and no retained retry queue is present in packet; later installed RefreshQuestCompletion may resend, so incidence depends on subsequent phase callbacks. Confirmed missing integration, qualified gameplay failure window. Install only after reviewing idempotency and performance; do not indiscriminately PatchAll.
