## Confirmed active persistence defects / qualified scope

### ECON-A — Structurally valid root can silently discard malformed economy records

Economy store Load validator checks only root name and schemaVersion equal to 1 or 2. PersistenceFile.TryLoad trusts validator then calls VerifiedRead(path), clearing write rejection. Actual parser continues past checkpoint whose ticks/revision do not parse; ImportCheckpoint ignores empty settlement ID; duplicate settlement IDs overwrite prior checkpoint; duplicate pending recipe keys overwrite; nonpositive/invalid pending entries are silently skipped. Negative checkpoint ticks/revision and unknown recipe IDs are accepted when parseable, with no range/schema child validation. Unknown root children are ignored by SelectNodes. Load then sets loaded=true.

Concrete source case: valid root schemaVersion=2 with a checkpoint settlement='S' ticks='invalid' revision='1' is accepted as a verified primary, skips record, and coordinator's next forced checkpoint serializes no S record. Existing .bak is replaced from that invalid-but-accepted primary before new primary is copied, so automatic recovery need not retain the prior usable record. This is an active load/save path even with no production API callers: legacy/imported stored checkpoints can be loaded and rewritten by bootstrap/coordinator. No assertion that the user's file currently contains malformed records or that a filesystem fault was reproduced.

Recommended after checkpoint: validate all child/identity/range/uniqueness invariants before admitting entire document, preserve rejected candidates using existing shared failure policy, stage parsed state before import; preserve schema 1 migration semantics. Do not enable offline production to test malformed load. Offline fixtures later: bad ticks/revision, duplicates, unknown/invalid pending entries, valid schema1/2, invalid primary+valid backup, malformed root children and forced coordinated save.

### ECON-C — Economy writer bypasses shared durable publication helper

SaveIfDirty:175 writes .tmp with XmlWriter then copies primary to .bak, copies tmp over primary and deletes tmp. It does not flush durable FileStream, validate completed candidate, or use shared SaveAtomic/RebirthAtomicXmlFile. Failed noncheckpoint save catches/logs and returns; ResetForWorldChange then clears checkpoints/replay and dirty/loaded regardless. A copy-to-primary interruption can damage primary; subsequent backup rotation can replace prior backup with damaged primary. Under IsCheckpointWrite exceptions propagate and outer SaveAll rollback may restore candidates; do not omit that protection or describe every checkpoint failure as permanent loss. Direct reset's save attempt outside coordinated checkpoint can swallow failure, but ordinary reset follows successful coordinated save, narrowing normal incidence. Fault sequence remains source risk, NOT RUN. This is same publication family as MP-023/MP-037 but separate economy file/caller; reuse shared helper instead of creating new persistence design.
