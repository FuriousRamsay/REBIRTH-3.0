## Real source-to-install route and lifecycle

Bootstrap/RebirthFresh_Init:78 invokes SurvivorInstaller.Install(mod). SDK default compilation includes core non-Debug sources; they are not prototype-only or Debug harnesses. Mod root is captured from InitMod. Loader resolution prefers that root, then the assembly directory, exact named loaded mod, other loaded mods containing backgrounds/traits/diets, then conventional game-directory probes. The three-file probe is only root discovery: Load still requires progression, condition/support profiles and four progression contract files. Fallback can select another mod with the same distinctive authoring trio if preferred/assembly roots are absent; this is local deployment ambiguity, not a remote file selection API.

Load uses immutable mod authoring via ordinary FileStream read/share-readwrite; these files are neither player saves nor server-received serialized definitions. It loads six main schema3 roots, appends generated aptitudes and validates progression contract roots schema1. Required root/schema/Req attributes and selected structural constraints throw. Ordinary IntAttr/FloatAttr return fallbacks on parse failure; FloatAttr does not reject NaN/Infinity. Direct starting skill value TryParse also lacks finite check, whereas starting_attributes and required finite progression contract attributes explicitly reject nonfinite input. Most unknown child elements are silently skipped; starting_attributes is deliberately stricter about unknown/repeated sections/duplicate IDs. Child helper uses first matching section for most collections. Do not claim a universal XSD or strict unknown-element validator exists.

Registry builds all ID dictionaries and support item/equipmentCVar/gear-item maps before swapping fields under Gate. Duplicate case-insensitive definition IDs and duplicate support bindings throw; missing bundle/progression throws. Models use private setters and copied read-only collections/maps. There are no public setters to mutate a loaded profile through a returned list. Lookup readers generally do not take Gate while install publishes multiple static fields; normal bootstrap/main-thread publication is the actual dependency. No concurrent reload overlap was established. Clear replaces all maps/hash/version and advances generation; successful install advances generation with int wrap1. Legacy background aliases map to current canonical professions at lookup; no aliases manufacture a new network identity.

Installer early returns only when installed+definition ready+background bonus ready. It loads authoring, computes version, runs diagnostics, preloads diet catalogue and installs registry/log gates. Definition-phase exception clears both registries and reports failure. Later runtime steps run independently through catching RunStep: mode, background bonuses/profile store, persistence/creation/hold/gear capture/network/FirstEntry/progression/Condition/statistics/party identity, UI last. Any exception leaves installed=false but definitions preserved for review/retry. Already-successful substeps must own idempotence; the parent installer does not roll back every earlier hook. RunStep only treats thrown exceptions as failure; a returned text containing FAILED is not parsed. Do not invent atomic rollback or a blanket per-subsystem retry guarantee from this installer alone.

## Diagnostics are not authority admission

AuthoringValidator exhaustively checks declared IDs/refs, expected roster/counts, trait availability/reconciliation, skill/attribute bounds, diet identity/points/rules, support schema, localization keys and referenced visual assets. Component target/phase/op whitelists are explicit; generic runtime target acceptance delegates to TraitGameplayModifierService. Native passive-effect names are not substituted for these custom target strings. Implementation state is metadata resolved by Reconciliation, not an executable route: IMPLEMENTED/CREATION_ONLY/PARTIAL/DEFERRED and availability are separate concepts. Generated aptitudes are explicitly creation-only and skip ordinary modifier-profile requirement.

**DEFINITIONS-A, confirmed admission distinction:** Installer:40–52 logs authoring errors and deliberately continues. Registry adds uniqueness checks, but it does not repeat all AuthoringValidator constraints. Thus diagnostics such as duplicate starting ItemId, unsupported modifier target, asymmetric conflict or missing visuals do not by themselves prevent installed runtime. This corrects SURVIVOR_CREATION_AGENT_TRACE's implication that duplicate starter item rows are prevented by AuthoringValidator: its duplicate check is real but diagnostic. Actual StarterItems:163–197 uses receipt prefix+ItemId, so duplicated rows of the same item would share a receipt rather than independently fulfill two declared entries. Current duplicate authoring or resulting item loss is NOT established; no client packet edits this authoring. Preserve existing receipt uncertainty design; do not report this as an active remote duplication exploit. Parent notified of the qualification.

Clamping models can also erase invalid original input before diagnostic checks: Trait.Points max0, StartingItem.Count/Quality min1, negative refund max-1, gear/timing minima. Parser error/fallback and model normalization are observable authoring semantics, not evidence that the author intended those values. Runtime CreationValidator/initializer finite/invariant checks from prior creation trace still matter; loader acceptance of NaN does not establish an accepted saved NaN character. Exact trait conflict validation checks selected IDs and bidirectional selected edge iteration; generated aptitude conflict asymmetry is intentionally allowed in diagnostics and enforced when selected.

## Semantic hash and compatibility

Hash V5 is independent of XML schema3. It sorts top-level records and set-like ID lists, preserves ordered modifier/support component sequences, encodes numeric floats invariant round-trip, includes starting item count/quality/block flag and optional starting attributes without perturbing old hashes when absent. Runtime/client compatibility uses this hash as previously audited. It deliberately omits visual/localization identity fields; those can change presentation without character incompatibility.

**DEFINITIONS-B, confirmed incomplete semantic fingerprint with qualified impact:** Progression.MaxNegativeTraitRefund is consumed in CreationValidator:131/point economy but absent from AppendProgression. Changing that local authored contract alone can preserve semantic hash while changing exact point admission. Current XML is max_negative_trait_refund=-1 and diagnostic expects it, but diagnostics do not block alternate values. Thus server and client locally differing only in refund cap can appear definition-compatible and disagree on valid selection; server still performs its own commit validation, so this is compatibility/UX reliability, not client authority to grant points. No such mismatched deployment was run. Knowledge.AssociatedSkillIds/ExplorerStatus, modifier ImplementationState and CapGroup descriptions/tuning are also omitted; these are presentation/reconciliation metadata in this reviewed scope and are not independently classified as gameplay compatibility bypasses. Skill SourceKey is omitted while LearnByDoingSource is included; do not claim every presentation edit either does or does not change the hash.

Generated aptitude IDs derive from non-Advanced authored skill IDs, two tiers only, +5/+10 costing1/3, same-skill tiers conflict, weakness map adds curated conflicts. Factory avoids generated duplicate IDs if authoring already contains them; arbitrary prefixed authored IDs therefore require normal validation/runtime parsing, not an assumption that every prefix is factory-origin. BuildId clamps tier1..2; TryParse rejects malformed or out-of-range suffixes. No network packet calls AppendGenerated or alters catalogue.

## Exact XML/native option semantics

RebirthXmlOptionConditionModApi.InitMod actually patches exact native XmlPatchConditionEvaluator.NCalcEvaluateFunction(string,FunctionArgs,bool); its installed flag is assigned only after PatchClassOnce succeeds and exceptions are logged/rethrown. This is an IModApi integration in addition to SurvivorInstaller, not a Harmony attribute-only reachability claim. Native FindActiveConditionalBranchElement walks ordered if/else children, evaluates cond, returns first matching branch or else, and rejects unknown conditional children. Native Evaluate uses NCalc and requires boolean result, wrapping expression exceptions in XmlPatchException.

Prefix handles only isoption/not_isoption/character_progression and otherwise returns true for native functions. Character progression requires exactly one string; accepted normalized aliases are Rebirth and Base/BaseGame (space/underscore/hyphen removed). Resolver priority is live GameManager world+Current sandbox code, then main-menu UiSession code, then Current fallback, then safe default. It does not query an invented network boolean or per-item requirement. Typed isoption takes three strings and explicit option map, validates expected type/value/defined enum; invalid map/type/value yields valid=false so not_isoption does NOT invert an invalid request into true. Purge-related options pass through release policy. These are XML patch-time branch functions, not dynamic runtime buff requirements and not world-save setters.
