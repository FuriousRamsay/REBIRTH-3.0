## Load/corruption and checksum limits

EnsureLoaded binds directory+scope, clears authority/read caches at boundary and menu, retries unavailable/corrupt/denied states rather than treating them as a new empty save. ConfirmedAbsent requires FileNotFound, not DirectoryNotFound or generic IO failure. Primary failure tries backup; no authority is installed until all selected record rows validate and IDs are unique. Scoped foreign rows are quarantined; unscoped dogs after a later process save are quarantined. Current embedded dog proof callers can promote a quarantined dog; helper itself accepts only stable ID and checks dog classification, so actual physical proof resides in the callers (StableIdentityStore72 and DogStateService.EnsureView313), not inside the store method.

TryLoad811–818 calls ReadRecord and ValidatePublication but does not compare persisted AggregateChecksum against ComputeRecordChecksum. The checksum comparison occurs in staged-write validation735 and diagnostic ValidateAtomicConsistency744. Thus a primary with changed covered data and stale checksum loads authority instead of selecting backup. This is a specific weak-validation extension to MP036; no modified-client or malicious-save exploit is established. Additionally checksum intentionally covers many domain revisions rather than all values: owner ID/state, world position, vitals and most dog data are not directly hashed. Changing an owner ID without incrementing OwnerRevision is invisible even to checksum diagnostics. Do not describe this hash as authentication or complete content integrity.

ReadRecord uses compatibility defaults for many missing/malformed scalars and ParseVector3 returns zero on malformed vector text. Nonfinite values that parse are rejected by HasFiniteNumbers. Unknown optional record elements preserve OuterXml; unknown required elements reject. Known-name detection is case insensitive but SelectSingleNode is case sensitive, so wrong-case known fields can be treated as known yet ignored; malformed-input limitation, not ordinary serializer behavior. Controller-fragment base64 errors become empty bytes in the envelope; native reconstruction has additional strict fragment validation and actual handlers remain a separate obligation.

## Mutation, views and authority

Mutate works on typed detached copies, checks expected record identity/epoch after reentrant callbacks and copies again before installing authority. TryMutateExisting additionally compares AggregateRevision. Reset increments epoch; per-row publication invalidates cached views. Snapshot and TryGet return detached graphs; SnapshotViews returns cloned ordering array. Read-only arrays own newly allocated backing arrays, nested DTOs become immutable views, controller bytes and dog learned-command sets are copied. No mutable store reference leak was found in these three full files. Native reconstruction and appearance are shared only as immutable composed objects (their helper contracts were read in prior tranche).

Generic mutation validation requires core records, creation enum, supported dog enums, finite numeric fields and matching native reconstruction binding. It does not independently validate ownership strings, persistent actor identity, nonnegative item counts/slot bounds or item codecs for arbitrary in-memory callers. Disk slot readers reject negative counts and duplicate equipment slot IDs, while native custody reconstruction applies stricter evidence checks. These APIs are internal gameplay persistence tools, not network-authenticated endpoints; no remote caller bypass is inferred from missing IsServer checks here. Actual authoritative gameplay callers and request handlers govern actor permissions, as earlier companion/network traces establish.

uint aggregate revision increment wraps max to1 via Math.Max; theoretical replay collision requires billions of mutations and is not an observed defect. Reentrant mutators publishing another row are allowed; same-row replacement/reset invalidates the original candidate. RollbackMigrationToBoundary and UpsertMigrated have no external production caller found in the Scripts reference scan; do not apply their weaker semantics to current importer, which uses TryCommitMigration.

## Save/native capture and lifecycle

Save refuses loaded cross-directory/scope publication, captures runtime envelopes then rechecks scope before disk write. Capture skips prepared restoration candidates, stages every validated row before publishing the set, and refreshes unloaded row manifests during checkpoint. The coordinator587 commits aggregate after all other domain stores and before timeline checkpoint so domain hashes describe that generation. Domain manifests are checked by diagnostics; they are not a load admission gate in TryLoad. Non-checkpoint aggregate Save can reflect the current domain file generation without promising a coordinated checkpoint.

Runtime capture replaces Ownership/Order with runtime snapshots, retaining the owner's canonical runtime string but dropping auxiliary ownership/order details not copied in that assignment. Whether these fields carry gameplay policy requires actual consumers; no new active permission change established. Native capture binds original current actor/custody and clears reconstruction when capture is unqualified, as the prior persistence trace details. This serializer does not create or release an offworld actor, and doesn't enable held Work. Native restore/publication stays governed by parent's complete installed release chain.

WriteRecordsLocked writes a flushed temp file, rereads/validates every record plus checksum/count, preserves quarantined source separately and uses DurableFileCommit. On committed primary with backup-refresh failure, memory remains on the committed generation and dirty remains true for retry; no rollback behind durable bytes is reported. TryCommitMigration and resolved appearance publication swap memory only after this disk boundary. Source inspection only, no failure injection.
