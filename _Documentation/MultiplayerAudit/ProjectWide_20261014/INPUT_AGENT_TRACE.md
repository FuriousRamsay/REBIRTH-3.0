## Confirmed INPUT-A: cruise postfix bypasses native driver input ownership

CanDispatchCruiseAction requires player+Actions.Enabled, attached EntityVehicle, own UI manager and !IsInputActive. It does not require player==vehicle.AttachedMainEntity, native driver slot, alive player, or modal-window exclusion. Q action is accepted for any attached rider. TryConsumeCruiseToggle keys state only by player's entityID and cycles0/off ->1/normal ->2/turbo ->0.

Actual native EntityPlayerLocal movement branch calls AttachedToEntity.MoveByAttachedEntity(this) for every attached local rider. Native EntityVehicle.MoveByAttachedEntity assigns vehicle movementInput.forward/strafe/hop/brake/run only inside _player==AttachedMainEntity; remaining rider camera code runs outside that check. REBIRTH postfix executes after this native method for all such riders, invokes cruise toggle, and writes shared vehicle movementInput.moveForward=1/running based only on activePlayerEntityId. Thus passenger Q can change the local vehicle input object even when the native driver guard deliberately skipped movement assignment. This is concrete source-level input ownership bypass, not proof that a remote passenger can drive the authoritative server vehicle; authoritative vehicle simulation/driver packet acceptance remains parent vehicle topology scope. No multiplayer/game reproduction occurred.

Cruise state also lacks exact vehicle/world/seat identity. It clears when the same active player gets a movement update while not attached, or native accelerate/back/brake input cancels; no explicit attach-change/seat-change/world shutdown reset. Existing seat transfer intentionally retains AttachedToEntity and avoids Detach, so driver->passenger transfer need not pass the on-foot reset branch and can carry cruise state into passenger posture. Two local player managers would share one static state; split-screen behavior not verified. Different world reusing active entityID can expose old state unless an intervening on-foot update clears it; normal world startup ordering not demonstrated, so cross-world carry remains qualified.

Console guard explicitly blocks cruise dispatcher and clears vehicle movementInput in vehicle postfix, independent of native PlayerMoveController guard. Modal/text input prevents a new toggle through IsInputActive but already active cruise injection itself does not independently check window focus; whether cruise should pause in management is product behavior, not automatically a defect. Native accelerator/back/brake cancels (aircraft brake exclusion retained). HUD reads only local dispatcher state at20Hz and shows offscreen when state0; it does not establish authority.

## Persistent keyboard/controller action contract

PlayerActionsRebirth defines17 actions:5 music,4 vehicles, QuickStack,Recall,card-style,copy shape,3 minimap,ore sense. All declared applies Both/allowRebind true; ControllerRebindableActions includes every action. Native ActionUserData exact constructor confirms final supplied true is allowRebind, not doNotDisplay. All joystick defaults intentionally empty. Keyboard defaults: cruiseQ,seatShift+J,camperM,cameraHome,QuickStackShift+Q,RecallQ,cardShift+L,copyF,minimapPadEnter/PadPlus/PadMinus,oreShift+O,musicBackspace/Return/Minus/Equals; MusicStop is listed/rebindable but default unbound.

ActionSetUserData establishes conflict sets with native local/vehicle/permanent sets and adds REBIRTH reciprocally. It does not add GUI or global sets as native conflict authority, although conflict warning scans all sets AFTER native reports a conflict. Native controls still decide whether candidate is conflicting. SharedQ is intentional context-dependent cruise/recall; debug God collision only blocks shortcut when actual configured action binding equals God and DebugMenuEnabled, not merely being in debug mode. QuickStack signal owns its frame before recall fallback, so blocked Shift+Q never becomes Recall under backends reporting both simple/chord press. Copy and ore dispatch occur earlier and can also act in a frame if user deliberately binds them the same key; conflict list does not impose exclusive semantic arbitration across every custom action.

Registration reads SdPlayerPrefs ActionSet_rebirth and loads saved action set. Exact legacy Shift+C companion-card binding text (punctuation stripped, case-insensitive) migrates to Shift+L and writes saved set; all other binding text preserved. This heuristic cannot distinguish a user intentionally choosing the exact old default from an inherited default; no separate migration marker/version. Native GameOptionsControls.Save iterates ALL registered ActionSets and writes ActionSet_<Name>; Load iterates same collection, so both keyboard/controller changes have actual native persistence. Native Import/Export similarly includes registered set. Bindings are user preferences, not world/player inventory state, and are not transmitted by these sources.

It refreshes local companion colors/collision (separate service authority) and card-style, then attached state routes cruise versus on-foot. They are independent consumers rather than missing dispatch branches in NativeControls. Whole minimap/music service not certified here.

## M camper shortcut, camera and seat integration seams

M is a true PlayerAction, not raw key polling. CamperModeInput installer invoked by CamperModulePatchInstaller137; its own PlayerMoveController.Update prefix calls Consume and WindowSelector.OpenSelectorAndWindow prefix intercepts exact map destination. Rebinding M still drives same semantic action. Native Map is suppressed only when Consume returns true for focused shortcut; map stays available outside valid camper context. Network mode revision/world/identity mutation body is parent audit, not recertified here.

Shared installer actually calls Camera.Install; full camera pose/physics behavior parent scope. Its scoped Poll has no explicit ConsoleInputGuard check; whether legacy console is covered by native IsInputActive/bAllowPlayerInput remains native-window dependency, not asserted seat-behind-console defect. It should not be assumed protected solely by an early return inside the separate common method. Seat server/occupancy/owner/body details remain parent.
