## Native join ordering confirmed

The installed Assembly-CSharp.dll (SHA256 FCEEC27300FFD3A1F97B097E43B60F3B07597F441E7ECBC6E1B59EEBB234C705) decompilation shows GameManager.RequestToEnterGame invoking PlayerJoinedGame before ID mappings, localization, WorldStaticData.SendXmlsToClient, WorldInfo and GameStats. RebirthFreshAdvancedFarmingModApi registers this event and sends a targeted sandbox snapshot; PlayerSpawnedInWorld sends a targeted resend. This confirms the source-level enqueue order claimed by the comment, not runtime packet delivery or client application order. The same ModAPI invokes runtime startup before farming-state reset, and clears sandbox transport state on GameShutdown. Farming helper reset implementations still require their own review.

The dedicated parser only runs for GameManager.IsDedicatedServer. It resolves the configfile launch argument, reads a nested RebirthSettings section, accepts its attribute or child-property code, validates through TryDecode, and falls back to per-world settings on absent/invalid configuration. Its comment about native ServerSettings parsing is not independently proven by the GameManager extract; the native configuration parser remains a separate dependency. The codec beginning verifies prefix, supported version and triplet alignment, seeds historical defaults and validates individual option ranges; the remaining codec branches and application side effects are still pending.

The bounded ToClient snapshot supports early join before a World exists. Client acceptance requires a connected nonserver transport; retained snapshots are scoped to the actual server-connection object. New transports may start at lower revisions; invalid codes are rejected before consuming the new-transport force-load opportunity. Within a transport, older revisions are rejected and equal revisions may repair initialization. GameStarting reapplies retained state or uses a temporary conservative configuration; shutdown clears transport state and resets runtime options. This supplies the dependency identified in the tree audit, subject to full codec/lifecycle callsite review and actual join validation.

Authority loads per-world settings before native definitions; dedicated settings can intentionally override them, preserving the world's Purge theme. Existing worlds without readable options receive a legacy default; new saves use pending menu or last-used settings. The loader tries backup even when primary is absent, validates root/code and normalizes revision. The writer flushes and validates a temporary candidate, avoids copying an invalid primary over the backup and has a portable replacement fallback. These are stronger recovery checks than the separately identified workstation-security defect.

Remaining policy question: both missing and corrupt-both-copies resolve through the same fallback path, which can change progression/runtime policy in an existing world. Establish expected migration/recovery behavior and subsequent save callsites before prescribing quarantine; do not confuse a documented legacy default with proven corruption handling. The XML format attribute is written but not explicitly checked; code-version validation belongs to the pending codec review.

Later batch: early snapshot before GameStarting, same-transport resend, reconnect to lower-revision server, invalid then valid first packet, host/dedicated override, corrupt primary with valid backup, and runtime policy agreement across peers. Native transport origin enforcement is a dependency, not simulated multiplayer proof.

## Codec and policy application follow-through

Encode and TryDecode were read end-to-end (OptionManager lines 1365–1920), alongside LoadCode, LoadAuthoritativeSnapshot, ApplyNetworkSnapshot, ResetToDefaults and ApplyRuntimeState. Known options validate their encoded ranges; older codes explicitly preserve historical meanings for progression, fire, atmosphere, healing and boss-event thresholds. Unknown option IDs are intentionally ignored, but unknown code versions are rejected. Repeated known IDs are last-value-wins; this is deterministic across matching implementations, not by itself a multiplayer exploit. Reserved retired companion-inventory values are accepted and ignored. RGB channels are assembled and rejected above 255. Matching build/schema remains a validation requirement; these checks alone do not prove cross-version compatibility.

Current encoding explicitly emits the three trader options whose omitted defaults changed, and emits dependent configured values even when a parent currently disables them. Runtime application derives effective fire heatmap and POI-risk/sense policy without erasing the configured snapshot. The remaining option declarations, setters, menu admission, policy implementations and native definition-load patches are not covered merely by this codec read.

The manager publishes decoded state and revision before invoking policy setters. No rollback surrounds those setters. This is a failure-atomicity investigation, not yet a confirmed defect: establish a reachable throwing setter before prescribing a transaction. Network receipt retains the validated snapshot before application and accepts same-revision resends; startup can force-reapply the retained snapshot. QuickStack ModAPI also applies the current manager at initialization, so initialization order and policy reapplication belong in the planned early-join checks. No runtime test has been executed.
