### Exact endpoint contract and failure custody

Physical tokens normalize to resource:S@x,y,z or resource:W@x,y,z; registry creates a single endpoint per normalized location/kind. Only static containers and workstation output are supported. Workstation output rejects credit; physical hauling provider rejects it as destination. The registry exposes no reset or unregister method. Source identity remains location-based, not an original tile-entity reference or save fingerprint. World-switch/incarnation consequences remain dormant lifecycle risks pending broader source-scope review.

GetAvailableDebitQuantity counts only unlocked fungible stacks of the exact item type and subtracts endpoint-local debit reservations. IsFungible rejects metadata, installed/cosmetic mods, positive quality and nonzero wear. Debit planning repeats these conditions. Thus this endpoint deliberately does not collapse modified/equipped items into logical counts. Credit uses ItemClass.GetItem defaults and native partial stack compatibility, skips locked slots, and bounds total reserved credits conservatively across item kinds. It can underutilize capacity across different items; that is not duplication evidence.

TryReserveDebit/Credit validate ID/item/positive quantity, resolve a loaded, nonbusy source, then lock only endpoint dictionaries while checking current capacity and recording quantity. Same transaction cannot simultaneously reserve either direction on this endpoint. Reservation captures source.Revision after admission. This is logical local accounting, not a native LockManager reservation and not a frozen physical snapshot. Multiple endpoint reservations may prepare at the same revision; after one commits, another normally fails revision equality before mutation and its owning external coordinator must compensate the NPC leg. Expected retries/revision conflicts are not proof of loss.

Commit re-resolves source, checks revision, clones live original/proposed arrays, plans debit/credit, then calls source.SetSlot for each difference and MarkModified. It does not hold endpoint sync or a native lock over revision check and native writes. A time-of-check/time-of-use interleaving is structurally possible, but current Work callbacks are inactive and actual simultaneous game-thread mutation/reentrancy must be established before claiming a reproducible race. The revision is RemoteResourceAccess.ComputeRevision: length/type/count/quality/rounded wear only, not metadata, mods, tile identity or slot locks. Current debit and credit planning recheck locks and native stack compatibility, reducing some stale-revision consequences. Equality alone is not full original-object authority.

Reservation.Commit is idempotent only on the same reservation object: committed returns true; other terminal states reject. The endpoint itself has no durable transaction journal. All Commit outcomes run ReleaseOnce, including Indeterminate, releasing local quantity reservations. Rollback and Dispose do not undo committed/indeterminate writes; they reject or retain those states. External coordinator's separate outcome journal and retained Indeterminate state are therefore essential; endpoint accounting is not durable custody.

On a native write/MarkModified exception, Commit attempts restoration only for planned changed slots whose live values exactly equal this operation's proposed values. A different live slot is never overwritten; restoration failures yield an error containing indeterminate. Reservation translates that to typed Indeterminate, which the external coordinator recognizes and refuses unsafe NPC compensation. This is conservative: even an unattempted slot still equal to original can cause Indeterminate because it does not equal proposed. Do not call that false failure a data-loss finding; it intentionally withholds unsafe proof. Exact-value comparison is also not an incarnation/ownership token: a same-value intervening writer cannot be distinguished. Native reentrancy evidence is needed to elevate that residual risk.

Static wrapper SetSlot fetches current storage each time and UpdateSlot; MarkModified calls SetModified plus live-sync notification. Workstation output wrapper clones current output per slot and assigns it, then MarkModified sets modified and invalidates the cache. Both wrappers can silently return if source disappears. Endpoint Commit has no explicit post-write readback/original-tile binding. A disappearing/replaced source could therefore return success without the intended mutation if it changes during callbacks; this remains a dormant conditional risk until actual callback/reentrancy or off-thread reachability is proved.
