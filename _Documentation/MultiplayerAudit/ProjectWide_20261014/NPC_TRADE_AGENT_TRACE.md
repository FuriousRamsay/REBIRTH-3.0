## Confirmed findings for parent triage (local labels, no shared MP numbers allocated)

### TRADE-A — Catalog advertises wildcard offers that quotation cannot resolve

TradeService.cs:70–79: GetForProfile includes exact profile OR '*'; TryResolve only performs Offers.TryGetValue(Key(profileId,itemKey)). Quote:200 calls exact TryResolve(runtime.ProfileId,itemKey). Defaults:123–126 register only '*'. EconomyLogisticsClosure.cs:143 inspected registration adds global iron/cloth/water/repair at '*', alongside named profile rows. Thus a real non-'*' profile receives wildcard rows in catalog, but requesting one returns 'No authority-side trade offer exists'. This is deterministic source mismatch, affects local and remote identically and does not require committing inventory to reproduce. Exact profile offers can still work. Wildcard duplication with an exact offer can also consume UI slots; catalog sends at most 12 while UI displays only six without pagination. Do not label the whole NPC trade implementation unreachable.

Recommended narrow correction after audit/checkpoint: exact-profile-first fallback to '*' consistently for catalog and quote, with deterministic deduplication; preserve configured price precedence. Test wildcard-only/default, exact override, catalog ordering and both directions.

### TRADE-B — Consumed parent trade has no durable recovery of a completed first leg

TradeService.cs:263 marks consumed before mutation; 274–319 performs two independent gateway calls; 285–288/307–310 return a reconciliation message for Indeterminate/RollbackFailed. QuoteRecord contains only quote + Consumed, all in memory. PruneExpiredLocked:427 removes consumed records immediately when catalog quotation/report prunes; ResetForWorldChange:448 clears all. There is no TradeHandler resume/reconcile/query operation. Gateway persists individual item/count/direction transaction outcomes, not parent actor/quote/price/phase/second-leg obligation. Thus interruption/exception after first success and before definitive second/compensation leaves no retained trade coordinator obligation through reload. Router catches handler exceptions and returns HandlerFailed; retry of quote is consumed, then unavailable after prune/reload. Ordinary definite second failure is compensated, so this finding is specifically interrupted/uncertain/failed-compensation recovery, not a claim that every trade loses items.

The durable external fingerprint includes AuthorityKey (Gateway:643–648), while quote commit creates a fresh random lease and disposes it; old lease is not recoverable after restart. Reissuing the same leg with a new lease is both unsupported by current trade interface and fingerprint-conflicting. Returning 'requires reconciliation' is honest uncertainty handling but no implemented trade settlement path.

Recommended narrow correction: retain parent original trade and proven/unknown legs with actor/NPC/endpoint identity and exact amounts, bind recovery to original operation while granting fresh authority safely; do not automatically refund unknown payouts. Required cases: failure between every leg/publication, definitive refusal vs uncertain endpoint, failed compensation, timeout/lost reply, disconnect/reconnect/new entity ID, save/reload, duplicate commit. Preserve original economy; no redesign authorization inferred.
