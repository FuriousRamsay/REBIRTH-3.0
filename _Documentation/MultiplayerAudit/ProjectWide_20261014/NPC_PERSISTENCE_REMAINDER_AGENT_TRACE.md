## Confirmed source findings

1. **Stable identity semantic validation can bypass positional safety with NaN.** StableIdentityStore.EnsureLoaded accepts the root/version before rows, records a verified load, skips invalid ID/integer rows, overwrites duplicate stable IDs, and ignores float.TryParse success for x/y/z. NaN is not rejected. BuildCandidates includes a non-exact compatible candidate when its NaN squared distance fails the `> radius` rejection. In TryRestore, NaN similarly fails the `> confident limit` rejection; a sole compatible positional candidate is selected and rebound. This is a concrete malformed-sidecar recovery failure, not a remotely demonstrated exploit. It extends the existing weak persistence validation family: a root-valid primary does not trigger backup recovery merely because rows are malformed. Missing/invalid coordinates become zero. Modern dog embedded identities normally avoid this heuristic; pre-v231 dogs and embedded-binding failures fall back to it, and generic NPC activation invokes TryRestore when permitted. Exact-ID non-dog NaN distance instead fails the <=64 check and remains unresolved; do not generalize the positional branch to every matcher.

2. **Identity audit cache is omitted from the unexpected-world discard.** IdentityAuditLedger has a single `loaded` bit and no save directory binding. Normal successful ResetWorldScopedState calls ResetForWorldChange, but both ResetUnexpectedWorldScopedState and coordinator ResetForUnexpectedWorldBoundary omit it. If save A's ledger was loaded and shutdown cleanup fails before B becomes current, the later coordinator CommitStore(identity-audit, SaveCheckpoint) sees loaded=true and writes A's cached entries to B's current GameIO path, replacing B's entries. Even an empty loaded A cache can erase B's existing ledger. This is a source-confirmed exceptional transition defect, extending the already recorded incomplete unexpected reset family; it does not transfer item custody or prove ordinary shutdown contamination. Append has no production caller found in the Scripts source reference search, so do not claim ordinary identity admin operations actually append audit records. The checkpoint caller is active independently of Append.

3. **Root-valid audit rows can also be silently dropped.** Audit loader validator accepts only root/version; malformed sequence/time/succeeded rows are skipped and valid rows sorted/trimmed to256. A subsequent checkpoint normalizes that partial representation without semantic backup fallback. Ordinary Append save catches failures unless inside a coordinator checkpoint; checkpoint failures propagate. These are forensic persistence limitations, not reward duplication.

## Authority, scope and recovery

Stable identity mutations require authoritative server. Remote clients receive runtime state through existing packet paths rather than selecting sidecar identities. TryRestore removes a chosen pending record before RuntimeRegistry.TryRebindStableId and restores it with unresolved diagnostics on failure. Embedded dog binding checks compatible aggregate profile/removal state, and duplicate live embedded projections are deferred for retirement by Foundation. Legacy durable dog fallback searches compatible durable ownership/name candidates; this is intentionally weaker migration evidence, not current physical owner authentication. No claim of an ordinary owner takeover is established.

SaveScope observes a live world, hashes canonical lowercased save directory with a fixed namespace, and increments process generation on directory changes. Menus do not advance generation. Same-path save replacement has the same scope fingerprint; determining an actual stale identity recovery requires the native save creation identity and lifecycle caller, not this path hash alone. StableIdentityStore does track loaded directory, clears old pending state on directory switch and rejects saving its loaded state through another directory. Foreign-scoped rows are skipped; unscoped later-save dog rows are skipped. These protections are stronger than IdentityAuditLedger's cache.

PersistenceSchema telemetry calls VerifiedRead for accepted documents, tracks upgrades and copies a migration snapshot before serialization. Its telemetry dictionary is keyed by store ID and persists across worlds; status may say HEALTHY from primary-file existence even after rejected loads, so it is not itself a write-permission proof. Shared PersistenceFile's blocking/quarantine mechanism remains authoritative and was full-read in the earlier social tranche; no claim that wholly invalid XML can simply overwrite protected primary data.
