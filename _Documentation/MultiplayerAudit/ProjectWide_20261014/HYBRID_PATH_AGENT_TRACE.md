## Admission, runtime state and path safety

Server-only state dictionary keyed entity ID stores exact EntityAlive and target object identities; replaced entity or target resets direct/cooldown/geometry state, so recycled ID alone cannot inherit state. EnsureWorldIdentity clears dictionary when next eligible callback observes a different World reference. Dead/player/no-target removes state; no usable path clears direct flag but retains record. Native path signature hashes all points/length/current index and invalidates cooldown/vertical cache on geometry change. Same-tick failed acquisition is blocked. Initial rejection cooldown40ticks can be reset by route geometry change as designed.

Special movement rejects jumping/swimming/elevator/climb/temp/unreachable/side-step. Target prediction0.05sec; live vertical separation<=1.25m and every remaining native path segment<=1.25m. Entry native route may deviate no more2m horizontally from line between entity and native route endpoint. Once direct, route deviation is not rechecked until other fallback; vertical geometry still qualified. This is intentional direct-to-moving-target behavior, not a route-node shortcut as some registry text says.

Body clearance uses controller-scaled sphere radius max0.08,0.9radius+0.05, from mid-body transform to target mid-body transform with EntityMoveHelper collision mask and Ignore triggers. Movement destination uses predicted target world position while sphere tests current target transform; prediction can move destination beyond tested endpoint. Floor/support/drop sampling across direct line is absent; path vertical guard checks native nodes, not actual direct-line terrain. These are concrete safety bounds and potential edge cases, not a demonstrated pitfall/collision defect. Native movement collision remains authoritative. Clearance every other game tick offset by ID while direct; new/geometry-changed entry always checks. Stuck checks10ticks, movement<0.05m with remaining>1.25m ->40tick cooldown. Attack stop at80% safe held-action range, fallback1.5m; Stop native calls clearPath. This deliberately destroys current native path at in-range stop, requiring AI to request a later path if target moves.

## Persistence/lifecycle boundary

No custom saved path or state packet exists; path state is transient. Enabled is runtime option, not a shadow toggle. Dictionary strongly retains entity and target objects until removal or new-world eligible callback/disable. No unload/death lifecycle hook or shutdown reset in this module clears States. A dead/unloaded entity that ceases helper callbacks cannot execute RemoveState; same-world churn therefore retains stale object records. Entity-ID reuse evicts a record only when replacement gets a usable eligible path. World replacement clears on next eligible callback, not immediately during teardown. Source-confirmed retention gap; no memory benchmark or cross-world gameplay corruption demonstrated. Bound cleanup to actual entity unload/death/world boundary while preserving object-generation safeguards.

Despite filename ConsoleCmdRebirthHybridPathCapture.cs, actual preserved console class is ConsoleCmdRebirthHybridPathPerformance (rbpathperf/rbpathbenchmark), Debug only. It executes on server, resolves requester from native RemoteClientInfo else primary, bounds finite input20..180sec, permits one benchmark, five-second warmup; allocates frame buffer before measurement. It reports same-start smoothing state only and cannot guarantee population/options unchanged during measurement. No benchmark was executed.
