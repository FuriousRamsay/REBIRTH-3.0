`RebirthCamperCommittedItemSound` uses the native item-stack `PlayPlaceSound` contract: the moved item's SoundPlace override, otherwise the native slot's configured place_click clip. It identifies a stack actually depleted from the authoritative actor image. It never invents a generic sound identifier or mutates item data.

Defense calls it after successful local item publication, or after a matched remote operation's authoritative actor merge. Session operation identity prevents repeated result packets from playing twice. Query, failed admission, item-free mode/toggle changes, no-op refresh and removal-only actor credits produce no placement sound.

Energy calls it only after `OwnerHold.Retire` validates the after-image and removes the operation's retained hold. Both host and remote owner receipt paths already use that shared method after committed vehicle publication. A duplicate retirement has no retained hold and returns without audio. This covers actual source/component/fuel item debits, rather than playing on asynchronous command admission or repeated snapshots. Durable custody and packet schemas are unchanged. Recovery without an in-memory hold does not replay historical audio.
