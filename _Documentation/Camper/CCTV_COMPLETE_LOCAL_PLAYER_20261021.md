Confirmed cause: SDCSUtils.CreateVizTP creates the native rig but generates body/equipment/hair only when isFPV=false. CreateVizFP supplies basePartsFP and first-person equipment, suppresses head/hair and assigns HoldingItem layer. First-person materials also use _ClipFPV. Thus the CCTV can see the limited FP torso/arms with no complete head. Changing camera layer9 or renderer enabled state alone cannot generate missing meshes. A render-callback native view switch would regenerate the whole rig every frame and is unsuitable.

Chosen native solution, parent approved: once on CCTV OpenCamera, save the local player's exact prior bFirstPersonView. If first-person, call native SetFirstPersonView(false,false) BEFORE instantiating/parenting the CCTV camera. This generates complete third-person character appearance using native equipment/hair/head/animation handling. On StopCamera, destroy the CCTV/texture then restore the saved native view exactly. All normal close/failed-open paths already call StopCamera. A previously third-person player is retained unchanged; no per-frame mesh regeneration. No direct global player layer manipulation, head scale hacks, detached appearance clone or material replacements. Native backing gameplay camera temporarily uses third-person while CCTV is open; exiting restores first-person when it was originally selected. Preferred-view preference is not changed by this helper.
