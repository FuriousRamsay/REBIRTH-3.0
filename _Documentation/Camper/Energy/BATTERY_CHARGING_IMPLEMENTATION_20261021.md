## Native evidence and chosen policy

Current installed `Assembly-CSharp.dll` was decompiled for `PowerBatteryBank`, `VPEngine` and `PowerItem`. `PowerBatteryBank.HandlePowerReceived` caps incoming power to `InputPerTick`, invokes `AddPowerToBatteries`, then subtracts its actual `LastInputAmount`. The publicized `AddPowerToBatteries` updates the original battery `ItemValue.UseTimes`, traverses slots from the last slot, requires at least one integer use point of missing charge, preserves item quality/capacity and reports accepted input. `PowerItem.SendHasLocalChangesToRoot` only marks this item and existing parents dirty, so invoking it on a detached installed bank does not require a world tile entity.

The installed vanilla `batterybank` definition uses `InputPerTick=5`, `ChargePerInput=1`, `OutputPerCharge=90`; REBIRTH's industrial bank uses `InputPerTick=10` and inherits `ChargePerInput=1`. The existing native power cadence is 0.16 seconds. We invoke the same native charge conversion once per elapsed native period, capped by that bank's input acceptance. Battery item `UseTimes` is decreased only by the native method, preserving quality-dependent native capacity. Full/off/empty banks do not consume funding. Nonstandard custom `ChargePerInput` values other than 1 are refused because the installed native method can debit more input than its argument for such conversions; current supported vanilla and REBIRTH bank definitions both use 1.

`VPEngine.startEngine/stopEngine` maintain `EntityVehicle.IsEngineRunning`. Eligibility checks that native flag, a real player in driver seat 0, and fuel remaining, with the native zero-fuel-usage sandbox option honored. There is no speed threshold. A parked vehicle with its engine off produces nothing; a genuine running engine idling with its driver remains eligible, as does slow driving. A newly observed engine start waits one processing interval rather than awarding charge for the preceding engine-off interval. This uses native engine fuel behavior; no extra fuel model or physical alternator simulation is added.

The configured alternator output is **50 W**, charging only. `alternatorWatts` is optional in `Config/RebirthCamperEnergy.xml`, defaults to 50 for older configuration files, permits 0 to disable and is bounded to 0..300. It is the total vehicle alternator budget, not an increase to bank acceptance: one vanilla bank still accepts only 5 W, and an industrial bank 10 W. Excess alternator budget is discarded each tick. It is never exposed as a source for lights, turrets or other consumers.

Solar cells keep their existing quality-based output: qualities 1..6 produce 17/20/22/25/27/30 W each before any native sandbox output multiplier, with six cells supplying 102..180 W. The existing loaded-chunk, daytime and full native sunlight (15) probe is preserved. Solar production now refreshes in Travel as well as Camp so installed banks can recharge while parked or travelling without another active device. Night/shade clears usable solar power as before.

## Accounting, custody and save behavior

`RebirthCamperEnergyRuntime.Tick` retains existing consumer priority and `Spend` semantics. It charges consumers first. The new `RebirthCamperBatteryCharging.Apply` sees only each solar source's remaining counted budget, then supplements that with eligible alternator funding. It checks enough input exists before invoking the native conversion and debits the exact accepted amount afterward, solar first. Generator fuel/power and battery discharge buffers are never charging sources. In particular, a battery cannot feed its own charging, and a generator cannot recharge it through this helper.

The per-bank charge rate is native, not a one-call-per-second approximation: fractional elapsed native periods carry in memory across short ticks. Work is capped to 64 periods (10.24 seconds) per processing call and excess time is discarded. Alternator funding never carries between calls. Exact station-save holds, fuel custody holds, energy holds, transfer holds, custody recovery, invalid immobility state, initial clock setup and unload reset the charge cadence/engine observation. The existing registered unload hook calls `PauseClock`; reloading the same entity cannot claim offline charging. Remote or noncurrent entities cannot enter authoritative Tick mutations.

Changed native battery stacks are already part of `RebirthCamperEnergyState.Encode`. The existing byte comparison triggers one normal revision increase, `Persist`, metadata publication, `SendSyncData(4)` and native vehicle save scheduling. Source removal uses the existing portable frame and retains the new charge. No energy save version, packet layout, source identity, item codec or custody receipt format changes. Existing source observation responses carry the updated original ItemValues; no new client-side charge mutation is introduced. No XML/localization/UI entries are required beyond the existing configuration attribute.
